# Spec F · Agent: task parse, executor, fallback loop

Design: `resources/docs/solution.md` §3.2 rows [C]/[D], §3.3, §3.4 (variables), §4 rows Clicking/Tool exposure/Agent loop/Model access, §5 Track 3 (3.1–3.3, 3.5, 3.7); Appendix F §4.1 (parse → executor → Jev → tool-use loop), §4.3 (Jev questions); Appendix E §4.4 (task-time use), §4.5 (rungs 0–3); Appendix G §4.2 (change-log probe), §4.3.4 (column alignment). Run book: [README.md](README.md).

## Problem

A task is a natural-language CRUD action against an app we may have mapped. On a mapped app it must run with two cheap LLM calls, no OCR and no agent turns: parse the task into typed queries, answer reads from the cache behind the change-log probe, replay stored procedures for writes, verify every step. The tool-use agent loop exists for the worst case only: an unknown procedure, an unsure parse, or a repair ladder that ran out. Every model call goes through OpenRouter; Jev answers the typed per-step questions.

## Owns

`app/agent/`, `tests/agent/`, `tests/fakes/llm.py` (a fake OpenRouter client returning OpenAI-style chat completions with scripted `content` / `tool_calls`, and a fake `decide` returning scripted `(answer, confidence)` pairs). Overwrites the A1 stub `app/agent/loop.py: run_task`. Uses `FakeSession` from A1, `observe`/`replay_target` from W, `ground` from C, `AppMap` from D, `need` from E through their public functions; never calls C's `elements()` directly and never edits those packages.

## Slices

**F1 · Task → queries with the fast model, and the model clients** (3.5 input; F §4.1 step 1, §4.3)

As the executor, `parse_task(text, entities, procedures) -> Plan(queries, confidence)` makes one `MODEL_FAST` call (JSON output) and returns `Query(op ∈ {read, create, update, delete, explore}, entity, where, fields, aggregate, key)`, where `entities` lists the cache entities with their display names and columns and `procedures` the stored `(op, entity)` names, so the model maps "facturas vencidas" to the Facturas node id with `where {Estado: Vencida}`. Rides here: `app/agent/llm.py`: the OpenRouter client (`openai` SDK, `base_url` OpenRouter, three tiers `MODEL_FAST` / `MODEL_VLM` / `MODEL_PLANNER` from env, a clear error when one is unset) and `decide(state, questions) -> {name: (answer, confidence)}` over Jev (`typesafe-sdk`, model `jev-latest`, `Choice` / `Noul` / `Score`, every question in one `system_one` call), with the same questions sent to `MODEL_FAST` in JSON mode when `TYPESAFE_API_KEY` is unset. Seam: the fake client and the fake `decide`; done when "¿Cuántas facturas vencidas hay?" gives one read query on the Facturas node id with `where {Estado: Vencida}` and `aggregate=count`, "Crea un pedido para Ruiz" gives one create query with `fields`, gibberish gives `confidence < 0.8`, and `decide` with no key routes to the fallback and returns the scripted confidence. Blocked by A1.

**F2 · Tools that return an observed effect** (3.1, 3.3; grounding from C4 and W2)

As the executor, I name targets, never coordinates. Low tools `click`, `type`, `key`, `screenshot`; mid tools `click_text(label)`, `fill_field(label, value)` (clicks the paired input, confirms a caret or text appeared in that bbox, else Tab), `read_region(bbox)`, `wait_for(text)`; high tool `navigate_to(screen)` following map edges. `navigate_to` acts on each edge through `replay_edge` (stored `xy` first, verified by destination, perception and an `xy` rewrite only on a miss). Every tool observes the screen through `observe(fb, map)` and grounds through `replay_target`: on a snapshot hit it clicks the stored bbox with no OCR; on a target that only moved it clicks the template-matched bbox (`fastpath: moved`); only on a miss does it ground against the perceived elements with C4. Every tool returns an `Effect(ok, changed_bbox, screen_id, signal, detail, cost_ms)` and never raises on a miss. Denylisted labels are refused unless the task names them. Seam: `FakeSession` + fixture element lists + a 3-node map with snapshots; done when `click_text("Facturas")` yields the Facturas screen id and a click inside its bbox with `rec_calls == 0` when the snapshot matches, a fixture with that button shifted 30 px yields the shifted bbox with `rec_calls == 0` and a `fastpath: moved` line, `click_text("Zzzz")` yields `ok=False, signal="S1"` after the perception fallback, `fill_field("Cliente", "Ruiz")` clicks the paired input then types, and `navigate_to("Facturas")` issues the stored edges. Blocked by **W2 · `observe`: replay or perceive**, **C4 · Grounding and Set-of-Mark** and **D1 · Screen fingerprint and map file**.

**F3 · Replay-first executor, end to end** (3.5; E §4.4; G §4.2)

As the evaluator, one NL task runs end to end through the entrypoint with the agent loop never called on a mapped app. `run_task` parses (F1), then a deterministic executor runs each query: `read` → `need(entity)` (E1 behind the change-log probe, then clipboard → OCR paging on a miss) → SQL for filters and aggregates → the answer; `create` / `update` / `delete` → the stored `procedure(op, entity)` replayed step by step with the query's `fields` as params (`observe` → `replay_target` → act → `settle(expect=edge effect)` → `changed_bbox` and screen id against the edge's expected effect) → verified by reading the record back and re-reading change-log page 1 (G §4.2) → write-through. `entity` is resolved from the task's word to the nav-map node id through `AppMap`, and E's column-alignment leftover callable is wired to `MODEL_FAST`. The hand-off to the fallback callable (F4) happens when `Plan.confidence < 0.8`, when `(op, entity)` has no stored procedure, or when a step's ladder (F5) is exhausted. One `MODEL_FAST` call writes the summary (free text + `data`); one `step` event per tool; the 270 s guard always writes the summary; the map is written back at task end. Replaces the A1 stub, so `POST /tasks` now does real work. Seam: the fake client scripted `[parse → queries, summary]` on `FakeSession`, a 3-node map with snapshots and one `create` procedure, SQLite in `tmp_path` with a seeded entity and a change-log entity; done when a lookup task ends `terminada` with the SQL answer, exactly 2 LLM calls, `rec_calls == 0` and a `sync.probe {scope: changelog, outcome: hit}` line, a create task replays the procedure with `rec_calls == 0` and a write-through row, a task on an entity with no procedure invokes the fallback callable exactly once, a never-finishing fake with a 0.3 s budget ends `fallida` with a summary, and the JSONL has one `step` per tool with `tool, args, screen_id, diff, outcome`. Blocked by F1, F2, **A2 · Task runner with budget guard**, **D3 · Planner view and routes**, **C3 · Grid detection**, **E1 · SQLite cache with probe and atomic swap**.

**F4 · Agent fallback loop that learns the procedure** (3.5, L1+L2 as the last resort; E §4.3 step 3)

As the evaluator, when F3 hands off, a `MODEL_PLANNER` tool-use loop receives the task, the queries parsed so far, the current element list as text (snapshot text on a hit, perception on a miss, the SoM image only on a new or unexpected screen) and the compact map, returns several tool calls per turn, runs them in order and stops the batch at the first failed `Effect`, max 8 tool calls per batch; every verified action upserts an edge (D2), and at the end the loop stores the step list as `procedure(op, entity)` so the next task replays it through F3. Prompt caching on the system prompt + tool schemas + map summary where OpenRouter passes it through. Seam: the fake client scripted `[click_text Cartera, click_text Facturas] → done` on `FakeSession`; done when the task ends `terminada` with a summary, the map file has a new procedure for `(read, Facturas)`, and a second run of the same task through F3 does not call F4. Blocked by F3, **D2 · Pre-warm and task-driven write-back**.

**F5 · Repair ladder wired into the executor** (2.6 end to end, §6; E §4.5)

As the evaluator, when a signal fires the executor runs D's ladder with real callables: rung 0 `inherit` + pre-warm on the session with node re-identification through `MODEL_VLM` (`ref_png` + SoM image); rung 1 in order fuzzy label → same role + cell → Jev `decide` (`target` Choice over the visible element ids, `effect_ok` Noul, `drift` Score, the old action as few-shot in the state; acted on only at confidence ≥ 0.8) → `MODEL_VLM` re-ground with the SoM image; rung 2 local re-explore on the session; rung 3 replan through `MODEL_PLANNER`; and F4 as the last rung. Every rung logs `drift {signal, rung, via, confidence, before, after, cost_ms}`; `run_task(..., mutate=kind)` applies an E §6.1 mutation first, the redesign kinds included, so the whole table runs through the real executor. Seam: fake client + fake `decide` + `FakeSession` + golden map; done when `rename` resolves with a `{signal: S1, rung: 1, via: "jev"}` line and no VLM call when the fake `decide` answers at 0.9, the same mutation reaches the VLM when it answers at 0.5, `unknown_screen` shows a `rejoin` line after the replan, and `version_bump` ends `terminada` with a `{signal: S5, rung: 0}` line. Blocked by F3, **D5 · Rungs 2–3 and rejoin**.

## Decisions already made

Parse → executor is the happy path and the tool-use loop the fallback (solution §3.3, F §4.1); replay from the saved snapshot before any perception (Spec W); reads behind the change-log probe (G §4.2); plain Python tools, no MCP, no agent framework (§4); text over images, SoM image only on new or unexpected screens; every LLM call through OpenRouter, never the Anthropic SDK or API; Jev is System 1 for the typed per-step questions, with `MODEL_FAST` as its keyless fallback behind the same `decide`; summary always written at 270 s.

## Assumed

- Model ids come from `MODEL_FAST`, `MODEL_VLM`, `MODEL_PLANNER` (human-filled placeholders in `.env.example`); tests never read them.
- Parse and Jev confidence gate 0.8; max 8 tool calls per batch; 2 LLM calls per task on a mapped app (parse, summary); summary call reserved 10 s.
- Jev answers typed questions only, never planning, field values, counts or dates (F §4.3). Its keyless fallback is a ~20-line JSON-mode adapter over the OpenRouter client, not a second dependency.
- Icon-only targets fall back to `MODEL_VLM` raw x,y from the SoM image (§8).

## Not building

Model tiering beyond the three env vars and cache verification (3.4/3.7; trigger: harness numbers above target); code-as-action; parallel tool calls; the `system-one-adapter` package (trigger: the hand-rolled fallback misbehaves and the package installs cleanly).

## Live checks (human)

One SIGECOM lookup through the deployed entrypoint with 2 LLM calls and a change-log probe hit; each write task from `harness/tasks.yaml` run once on SIGECOM so the learned procedures land in `memory/` with the map, then run again replayed from them; ≥95 % click hit rate on named targets (3.2); Jev escalation rate and the F §5 criteria on the harness; average step time and task time (3.4).
