# Spec C · Screen perception

Design: `resources/docs/solution.md` §3.2 row [E], §4 Perception row, §5 Track 7; Appendix H §4 (pipeline, caches), §6 (measured timings). Run book: [README.md](README.md).

## Problem

The model must pick named elements, never coordinates, from a 1280×800 framebuffer, and on a mapped app it must not run at all: the saved snapshot replays first (Spec W). Full OCR of a dense screen costs ~8 s, so perception must detect once, recognise lazily, cache by line pixels and re-read only what changed.

## Owns

`app/perception/`, `tests/perception/`, `tests/fixtures/expected/` (goldens written by these tickets). Reads `tests/fixtures/screens/*.png` (human-captured, read-only). Overwrites the A1 stub `app/perception/ocr.py: elements`.

## Slices

**C1 · OCR lines with lazy recognition and a line cache** (7.1, 7.6 line cache)

As the agent, `ocr(fb) -> list[Line(text, bbox, conf)]` runs RapidOCR detection once, recognition per line, angle classifier off, and a cache keyed by the hash of the line's pixels so a second call on the same screen does no recognition. Uses `app/perception/models/latin_rec.onnx` if the file exists, else the bundled default model. Lines under 0.8 confidence are flagged. Seam: `tests/fixtures/screens/facturas.png`; done when Buscar, Limpiar, Exportar, Código, Cliente, Fecha, Vence, Valor, Estado, Siguiente are found (accent-insensitive compare, so green with either model) with bboxes within ±10 px of hand-read rectangles, and a second call reports `rec_calls == 0`. Blocked by A1.

**C2 · Widget boxes, kinds, UI tree and label↔field pairing** (7.2, 7.3)

As the agent, `elements(fb) -> list[Element]` merges OCR lines with OpenCV boxes (contours + grid lines) into elements with `kind` (title, menu, button, field, select, link, header, cell, text) and `paired_input` for labels next to inputs, using containment, Gestalt grouping and kind rules. Seam: `facturas.png` plus one form fixture; done when Cliente pairs with the input below it, Estado with a select, Buscar is a button, Cartera a menu, the title a title. Blocked by C1. May split into boxes+kinds / pairing+grouping if `/spec` judges it too big (spec stays at 5 slices by folding C5 into C4).

**C3 · Grid detection** (7.4)

As the agent, `read_grid(fb) -> Grid(columns, rows)` names columns from the header row and returns one dict per row keyed by header text. Seam: `facturas.png` vs a hand-written golden `tests/fixtures/expected/facturas_page1.json`; done when columns are Código, Cliente, Fecha, Vence, Valor, Estado and rows equal the golden. Blocked by C2.

**C4 · Grounding and Set-of-Mark** (7.5, feeds 3.2)

As the planner, `ground(target, elements) -> Element | None` resolves a `Target(label, role, cell)` exact → fuzzy (stdlib `difflib`) → same role in the same 12×8 cell, and `som_image(fb, elements)` renders numbered boxes for new screens while `elements_text(elements)` is the default text list. Seam: element lists from the fixtures; done when "Buscar" → the button, "Facturación" → Facturas, an unknown label → `None`, and the SoM PNG has one mark per element. Blocked by C2.

**C5 · Incremental re-perception and screen cache** (7.6)

As the agent, `elements(fb, prev=..., changed_bbox=...)` re-runs detection and recognition only inside the changed region and reuses the rest; a per-key screen cache returns a known tree at once. Seam: `facturas.png` and a copy with one region repainted; done when only elements inside the region change and `rec_calls` ≤ lines in the region. Blocked by C2.

## Decisions already made

RapidOCR on ONNX Runtime, CPU only, classifier off (Appendix H §6: it flipped "Todos"); detect once, recognise lazily, cache by line pixels; hybrid OCR + CV, no GPU grounding models (§4); title text matched case-insensitively (H §6).

## Assumed

- Confidence threshold 0.8; fuzzy match ratio ≥ 0.8; grid 12×8 on normalised coordinates (shared with D1).
- Goldens are literals written by hand from the image, not generated by the code under test.

## Not building

Tesseract cross-check and upscale fallback (7.7; trigger: accent errors or hit rate < 95 % measured live); icon-only targets via the VLM's raw x,y (lives in F); learned detectors (trigger: a GPU).

## Live checks (human)

≥90 % labels found on 5 screens; CV box recall; pairing on Facturas + one form; grid JSON vs screen; timings on Railway (H §7).
